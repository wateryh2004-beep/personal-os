# 统一审美与项目规范体系

类型：决策记录。日期：2026-10-14（UTC+8）。所有者：余航。状态：以下方向已采纳；具体工程参数为实施基准，运行迁移尚未完成。

## 背景与依据

所有者指出系统普通、缺乏极简与美感，认证入口存在多余文案和标注，希望通过视觉引导与严格对齐组织界面。随后逐项选择暖白柔和方向、少量卡片的包裹感、深灰绿强调色、宋体标题与无衬线正文，以及带空间纵深的登录进入动画。

所有者进一步要求动画积极、充分设计，追求接近 Apple 的细节质量，覆盖每个具有动画的交互位置；并明确要求先建立规则、放入 GitHub、让后续 Agent 读取，再推进界面实现。

2026-10-14 所有者授权建立前述产品、设计、工程、数据、安全、验收、运行与 Agent 协作等完整文档体系。此授权用于仓库文档，不新授予生产数据库写入、真实密码修改、对外消息或付费资源权限。

## 已采纳选择

| 主题 | 选择 |
| --- | --- |
| 整体气质 | 暖白、柔和、舒展，长期使用舒适 |
| 内容组织 | 少量卡片提供清晰分组与包裹感，内部严格对齐 |
| 强调色 | 深灰绿，统一主要动作与选中/焦点 |
| 字体 | 页面主标题与重要展示标题用宋体/衬线，正文与操作用无衬线 |
| 文案 | 简短、直接；删除装饰英文、寄语和重复说明，保留必要标签与真实状态 |
| 动效 | 充分设计的纵深、形态与共享空间衔接；登录成功有明显进入感 |
| 文档 | 仓库主规范、统一索引、Agent 入口、决策与验收记录，覆盖全部讨论主题 |

## 实施基准与待验证项

具体色值、字号、圆角、间距、时长和曲线由维护者提出基准，在样板和真实设备上验证后可在已确定方向内调整，不需要把每个像素再变成单独审批。

首页舒展、工作区有序紧凑是实施默认，需通过真实任务核对。跨平台字体回退、完整深色方案、低性能设备的动效策略与测量结果仍需验证；不宣称所有者逐项确认过数值或效果。

## 取舍与后果

更多运动意味着需要完整处理连续操作、反向、卸载、焦点和性能；通过共享模式与可中断编排控制复杂度。宋体增加气质，也需要验证不同平台的字宽和可读性。轻卡片提供边界，数量由任务分组决定。

旧青蓝强调、全系统无衬线、禁止明显缩放/回弹的全局限制以及认证装饰文案与新方向冲突，由 [设计 v2](../design-system.md) 和 [动效规范](../design/motion.md) 替代。旧设计保留在 [历史记录](../history/design-system-v1.md)。
