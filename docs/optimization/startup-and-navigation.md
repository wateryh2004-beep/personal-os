# Startup and navigation: bounded October 7 change

Notes list entry had an HTML → client hydration → workspace API → database waterfall. Its read is now started by the authenticated server route, streamed under Suspense as metadata only, and seeded into the same owner-scoped tab cache. The navigator defers its redundant initial read only on the Notes list route; document routes retain their existing independent navigator read. Route-owned prefetch prevents competing API and RSC prefetch reads. Existing mutations, owner revision resets, document fetches and auth gates are preserved.

Bootstrap is accepted only for the current cache owner and a recent server payload. It cannot overwrite a newer local mutation or active request. Expired payloads use the ordinary authenticated API. No module-global server user cache, persistent browser data cache, shared response cache or authorization bypass was introduced. The existing Today GET schedules reminder reconciliation; it was not moved into speculative rendering.

Timing allowlists now cover Files, Leisure, Investments, Settings, Projects, Shopping, Travel and Reviews without recording record IDs/query text. Data-backed Files/Investment/Leisure views emit readiness; skeleton/FCP is still separate from useful content.

Checks: owner mismatch, stale payload, warm mutation, in-flight race, invalidation and duplicate-request tests pass; integrated unit suite, TypeScript, changed-file lint and Next build are run before publication. Actual browser CI records initial readiness, transferred JS and warm navigation using the production-built Notes loader and synthetic records. Both variants model a 150ms data read; the former hydration API additionally models a 250ms round trip. Measurements are fixture evidence, not live backend, real-user, China-network or platform-cold-start claims. Browser execution is blocked by this local executor's socket sandbox; CI remains the actual-browser acceptance gate.

The first actual-browser run revealed a warm-return regression: awaiting the server model before mounting the loader added its 150ms fixture read to warm navigation. This was not accepted as complete. The route now keeps its cache-backed loader mounted while a separate Suspense seeder consumes the streamed promise; it must pass a new warm-return assertion below the injected server delay. The historical navigation fixture explicitly calls revalidate to exercise its old client-read model independently of the new route-owned prefetch strategy.
