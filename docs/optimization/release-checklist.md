# Integrated release checklist

No production action is authorized by this checklist alone. The ten-item program remains draft until every acceptance gate and the parent's release decision are satisfied.

## Exact staged validation

- Clean install, full tests, typecheck, build and changed-file lint on the final tree
- Verify workflow: original mobile/Files/PDF flows, new search SQL, storage persistence, investment daily browser + PostgreSQL 16/17 concurrency, Notes cold/warm comparison
- Document continuity workflow: reader browser + PostgreSQL race, multipart interruption/browser + publication/cancel race
- Private OCR workflow: genuine bilingual scan/blank-page recognition, same-origin cold assets/browser cancellation and native SQL concurrency
- System backup workflow: official disposable PostgreSQL container, complete schema replay, fixture export/restore/re-export with true foreign keys
- Inspect actual responsive screenshots, not just pass labels
- Review the [bounded runtime security patch](../security/runtime-dependencies-2026-10-07.md), remaining triaged advisories, patched native-binary checks, and exact-head Chromium attribution evidence
- Re-read remote head and exact-commit checks; never infer that earlier green CI covers later integration
- Item 3: private content owner's explicit verified scope and acceptance; no answer bodies in repository

## Production migration review bundle

Review and apply only the eight new migrations, in filename order, before deploying code that selects their columns. Do not rerun historical migrations against production.

1. `20261007062235_cached_pdf_cover_jobs.sql`: owner-readable cover jobs and service-only leased queue RPCs
2. `20261007092752_document_reading_progress.sql`: source-version token and owner-scoped progress/CAS
3. `20261007093000_complete_module_search.sql`: security-invoker live projections for missing domains
4. `20261007093144_investment_daily_overview.sql`: owner cash/quote ledgers, atomic revision and validation triggers
5. `20261007093341_private_document_ocr.sql`: bounded OCR run state, owner/source guarded publication and durable provenance
6. `20261007093836_resumable_file_uploads.sql`: server-only upload sessions, leases, atomic publish/cancel and explicit cancelled document metadata
7. `20261007094000_persist_storage_budget.sql`: nullable owner profile capacity preference, existing RLS unchanged
8. `20261007102000_file_search_availability.sql`: final invoker guard and cleanup of rebuildable unavailable-file index rows

Four historical migration-file corrections exist solely to make clean schema replay/restoration work. They are documented in the backup runbook and are not a request to reapply those old versions to an existing database.

Existing service credentials and private bucket configuration are reused. No new key, bucket, public access, CORS rule, external backup destination or paid service is included. Any environment permission expansion requires separate review. Source/version metadata does not rewrite originals.

## Activation and live acceptance

- `PDF_COVERS_ENABLED` remains false until the deployed runtime, migration and authorized synthetic R2 smoke are accepted
- OCR binaries/models are generated by prebuild from pinned packages into same-origin static assets; originals never go to a recognition vendor
- Multipart/export routes request up to 300 seconds; confirm deployment runtime allowance without silently upgrading a paid plan
- Live synthetic smoke, when separately approved, should cover a small genuine scanned PDF, a multipart-sized synthetic file, interruption/reselection, sealed SHA verification, cover/reader/OCR/search coherence and export recovery of those fixtures
- Test records and originals are not automatically deleted afterward. Cleanup requires the separately authorized exact test objects; no broad orphan cleanup
- No real private document, production auth/R2 smoke or China/user-device latency test has been claimed by synthetic CI

## Non-destructive rollback

Keep new data/schema intact and disable the cover flag before diagnosing a rendering issue. Pause new OCR/upload actions if their acceptance fails. Do not delete originals, progress, accepted text/provenance, ledgers or snapshots.

Do not blindly redeploy an old build that predates the new cancelled state or OCR completion CAS. A rollback build must retain cancelled-state search/storage/export compatibility and the accepted-text race guard. Forward fixes or a compatibility-preserving revert are safer than discarding new user data. The current release has no destructive down migration.
