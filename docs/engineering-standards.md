# 工程、接口与依赖规范

状态：有效规范。维护日期：2026-10-14。适用范围：源代码、脚本、依赖与对外接口。架构事实和领域关系见 [架构文档](architecture.md)。

## 架构与职责

保持模块化单体：Next.js App Router、TypeScript strict、React、Tailwind、shadcn/Radix、Supabase/PostgreSQL，以及已有 R2/Microsoft/AI 适配层。版本以 `package.json` 和 lockfile 为准，不在规范里锁死未来版本。

| 位置 | 职责 |
| --- | --- |
| `src/app` | 路由、布局、页面组合、HTTP 边界 |
| `src/features/<domain>` | 领域输入校验、读取、变更、规则与状态 |
| `src/components/ui`、`shared`、`layout` | 公共控件、跨域界面和应用壳 |
| `src/lib/adapters` | 第三方网络调用与供应商协议 |
| `supabase/migrations` | 数据结构、权限与数据库规则的版本演进 |

默认 Server Components，客户端组件只承担浏览器交互和需要持久化的 UI 状态。普通写入优先现有 Server Actions；Route Handlers 用于 HTTP API、受保护读模型、OAuth、Webhook、流式响应与文件导出。不得为了保持某种形式而破坏现有边界。

领域代码不得随意绕过供应商适配层；跨域复用稳定的领域能力，避免双向依赖和共享可变全局状态。新增抽象应解决已出现的重复或明确的边界问题。

## 编码与组件

使用明确命名和严格类型，优先复用项目中已有模式。外部输入和环境变量在边界校验；不要用类型断言、`any` 或捕获所有异常来掩盖不确定数据。

错误要保留可定位的错误码与可恢复性；UI 只接收脱敏信息。空结果、无权限、配置缺失、超时和服务失败分别处理。

表单、焦点、弹层和可访问语义复用公共组件。布局由组件拥有；禁止依赖当前文案、数据是否为空或偶然 DOM 结构决定全站样式。

不要顺手重排无关文件。复杂函数按职责拆分；可读性和数据正确性优先于代码行数。注释说明原因与不变量，避免重复描述语法。

## 接口契约

接口或 Server Action 的新增行为写明输入、校验、身份与对象所有权、输出、失败、是否可重试以及副作用。公共契约变化更新调用者与测试。

读取明确分页上限、稳定排序和权限过滤；写入对重复提交、并发版本、外部超时与重试作出定义。幂等键由逻辑操作生成，不允许随每次重试变化。

状态码遵循实际语义。协议 API 返回适当的错误响应，不把登录 HTML 冒充 JSON 成功。不要把 token、原始供应商 payload、私有对象签名 URL 写入普通错误或日志。

供应商写入与本地提交无法组成同一事务时，明确“提案/待执行/处理中/成功/失败/冲突”边界；必要时先核对供应商结果再重试。Provider 超时不是确认未执行。

## 依赖与工具

新增依赖先核对已有能力，并记录用途、维护状态、许可、运行端、体积和替代成本。选择与任务相称的实现；技术选型已授权且费用权限未变化时，不因普通依赖选择重复请求批准。

提交对应 lockfile；CI 按锁文件安装。升级分离为可追踪变更，验证受影响的认证、编辑器、数据库、解析器、文件处理和动画流程。漏洞修复检查实际依赖路径与兼容性，不能只删除锁文件让版本漂移。

不要把安装脚本、原生二进制、动态下载或解析不可信文件的风险隐藏在普通样式修改中。生产构建依赖的资源生成步骤保留在构建链中。

## 环境与配置

`.env.example` 只包含名称、用途与安全的占位值；真实值进入对应环境的秘密配置。公开变量按用途登记，秘密变量始终 server-only，不能使用 `NEXT_PUBLIC_`。

功能缺配置时明确降级或拒绝相关操作，保留不依赖该配置的功能。不要打印环境对象、凭据片段或为了调试增加公开健康接口中的秘密信息。

本地、合成 CI、验证项目、Preview 和 Production 的对象、域名和凭据分别核对。当前缺少隔离 Preview 后端时，应关闭相关真实写入能力，不宣称已有完整隔离环境。

## Git 与审查

从核对过的基线建立任务分支，保留用户改动。提交围绕一个可理解的结果组织；PR 说明问题、最终行为、验证、运行影响和回退。默认通过 PR 合并，不直接向 main 写入未审查变更。

合并前检查基线变化和必要检查；出现冲突时保留两侧意图并重跑受影响验证。禁止无依据强推、静默删除迁移或通过跳过检查宣称成功。具体发布与合并授权见 [项目治理](project-governance.md) 和 [发布手册](release-operations.md)。

验证：受影响输入/错误/权限/并发分支有证据，公共契约有唯一实现依据，构建产物不携带秘密。
