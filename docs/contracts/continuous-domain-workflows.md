# 连续工作流：领域数据与交互契约

状态：本批实现契约。原十条迁移的固定数据库检查点已完成独立隔离验证；第十一条生产基线兼容候选未验，已推送界面候选仍有远程失败，发布未完成。具体范围见[2026-10-28 候选记录](../verification/2026-10-28-continuous-workflows-v3.md)。范围与最终证据以 [二十项规格](../specs/continuous-workflows-v3.md) 为准。主规范的身份、原件、事实、AI 和迁移规则保持有效。

## 时间规划与下一步

Microsoft To Do 和 Outlook 保持执行权威。`task_planning` 只保存用户估时、计划日与版本；`planning_availability` 按用户当地日期、明确 IANA 时区记录至多12段有序、不重叠时段。不是第二套任务或日程。保存使用修订号并发保护，审计保存修改前后；归档字段与创建时间保留迁移边界。

容量用未经分类筛选的整个日期日程求交集并合并重叠。明确 `free` 的日程不扣容量，其他状态保守视为占用。未配置可用时段、同步范围不覆盖、读取失败或达到上限，不得展示“空闲”或“装得下”。未知估时单列，已知任务的超载只代表下界。日程数据注明最近同步时间。空档选择只开预览，最终仍走已有 Graph 确认/去重/重读任务协议；不自动完成任务。键盘与触摸可直接编辑选区开始/结束，不依赖拖动。

时间格选任务、任务“安排”和任务拖放统一按已记录估时生成预览；未知估时必须明确输入本次时长或点击采用本次建议后才生成可提交预览。选择本次时长不写入任务估时，取消不创建日程。

项目的目标沿用 `description`；阻塞和显式下一项 To Do 分开保存。任务完成、归档或不可用时保留引用并说明，不自动代选或完成项目。高价值旧目标进入不可变项目版本；普通保存不改变项目状态。Inbox 项目资料以 `notes.project_id` 为权威，不额外复制一份 Graph 关系。

## 机会材料与面试续练

`career_material_checks` 表达用户指定的材料要求与人工核验，不是申请状态、自动投递或能力评分。私有文件原件、简历冻结状态与人工核验分开展示。核验记录关联确切文件修订与简历更新时间；对象变化后标待复核，不能静默沿用旧核验。保存拒绝归档、不可用及 Vault 文件；新引用采用现有 Vault restrictive policy。新字段不自动扩大 AI 上下文。

当前简历实现的定稿状态是 `approved`，草稿不能核验。核验采用明确的保留、清除、新核验意图；仅改备注并保留原引用，不更新原核验时间。新核验绑定用户当时看到的文件修订号和原始简历更新时间，SQL 同事务锁定并再次核对来源。时间以 `timestamptz` 精度比较，兼容 PostgREST 与 SQL 时间字符串表示，保留微秒；不将 JavaScript 毫秒时间作为版本键。旧草稿或资料变更不自动续签核验。

从卡点展开的记录必须是真实练习，显示样本与上次重点。续练保存独立 attempt，父练习属于同用户与同准备题目；场内追问还校验同场。原答案与反馈只读，用户明确记录是否改善；标签次数不是客观能力诊断。

## 复盘证据与逐项采纳

证据按用户时区与实际事件时间排序，保留创建、更新、完成、到期与日程发生的不同含义。每域有 one-extra 读取和覆盖状态，失败/截断不冒充空结果。用户选择证据后插入带链接的复盘文字，原有内容保留。保存重新核对每条引用的归属与本周期可见性。

AI 草稿先显示建议；每字段采纳前校对发起时基线。手动编辑过的字段不被覆盖。只在实际采纳后记录 AI 标志，明确保留本次实际使用资料作为 `context`；用户显式引用单独记录为 `cited`。复盘草稿、已选来源与采纳标记一起在有界同标签页草稿中恢复。采纳不自动保存复盘、记忆或决定。

## 简报事件与来源版本

去重 cluster 不等于同事件。`briefing_events` 与 `briefing_event_sources` 由用户明确归组，新增来源、同源内容更新、简报收录与个人判断分别显示。移出事件只归档关联，保留原文、版本与判断。

事件创建编号属于一次逻辑创建；结果未确认时保留编号，读回并核对，确认创建后下一次新建才使用新编号。刷新更新展示用的已保存版本，不静默推进尚未保存的编辑版本。

`feed_item_versions` 在同一数据库事务由固定触发器追加，记录实际观察到的标题/正文/摘要/来源时间。原有资料仅标“本次建立的基线”，不得捏造以前的变化。正文相同、仅刷新抓取时间不产生新内容版本。正文更新与快照任一步失败则整个写入回滚。版本禁止普通与特权客户端更新或删除。原文对照只表示文字差异，不能称已核实的新增事实；缺失来源时间标未知。私有来源正文不加入 URL、浏览器持久缓存或公共日志。

这批保留来源版本，不自动清除历史。生产回填规模与未来增长必须分别记录；本契约不擅自改变保留期限或开通付费资源。

## 数字、购后、旅行与闲暇

投资解释来自同一 canonical fixed-point 计算快照，附账户、币种、实盘/模拟、账簿修订、核对时间、有效记账及确切报价。费用和作废继续使用原计算逻辑；缺期初、成本或报价保持未知。点击数字能打开解释，回到原记录时展开所在折叠区并定位。不是券商购买力、交易操作或收益建议。

购后实际购买日 `purchased_on` 与旧“标记已购买”操作时间 `purchased_at` 分开。退换/保修截止完全来自用户记录，不推断政策、不因到期自动改变状态。票据原件仍在 Files；关联只保存受保护 ID。保存 CAS、日期校验和关联在同一事务，撤销“已购买”不永久删掉购后资料。

旅行的每日列表与地图共享明确站点选择。已知停留时段可跨午夜求重叠；未知时间或坐标不被猜测。重排先展示顺序及已知时间冲突，沿已有 CAS 确认管线。地图直线连点，不代表导航路线，不计算交通耗时，也不按时钟自动到达。

闲暇的 `duration_minutes` 是已记录总时长；只有口径明确的分钟进度可相减。页/集进度不换算分钟，进行中剧集的分钟口径不明时归未知。自定本次空闲1–1440分钟只影响浏览，继续/开始分别展示；未知单列，不悄悄放宽筛选。剩余为零不自动完成体验。

## 发布与恢复

项目、可用时段、任务估时、机会材料、购后档案和事件编辑在并发冲突后提供真实读回、当前输入与已保存内容对比，以及明确保留输入并以新版本继续或采用已保存内容的选择。读回本身不覆盖字段，读回期间的新输入保留；保留输入仍为未保存草稿，必须再次保存。成功仅结算提交时的快照，保存期间继续输入的内容保留。可用时段同时展示实际保存时区，不能仅替换修订号后默换时区。

当前十一条新增 migration 依序为 material sources → domain workflows → material receipts → inbox dispatch mutex → AI capture intents → practice intents → Scene state → Briefing judgment intents → agent run generations → Life request reconcile → production baseline，精确文件名及已验/未验范围见[迁移登记](../verification/2026-10-28-continuous-workflows-v3.md#十一条迁移与生产版本登记)。material receipts 引用 domain 建立的 owner 唯一键，mutex 再引用专门回执与来源规则。第十一条 `20261027175718_continuous_production_baseline.sql` 是生产元数据发现复盘函数/项目投影缺口后的前向候选；独立审查发现 completion 审计原子性问题，修复仍待复审和新 Native。它补缺失合法契约，并仅将匹配已知旧指纹/配置/ACL的 completion 前向升级为正文、版本、来源与完成/修订审计同事务；已是新版保留，未知定义拒绝，其余三个复盘函数（含 helper）及项目健康定义、ACL、投影仍按缺失补齐并保留，不重放十二个旧文件、旧 surface CHECK 或补造 history。生产 87 条 ledger 的最终对象不能被本地完整 99 条旧基线验收替代。当前十一条均未应用生产，不能改写既有已部署 migration。

新业务元数据、原文版本与关系进入 system backup；外部创建回执是技术执行状态，排除恢复和重放。原十条固定检查点已将官方实际生成文件、native catalog 与候选映射比较；第十一条所需四个复盘函数的候选类型参考同一官方产物，但新完整候选仍须实际生成和比较。手写候选映射本身不称官方生成文件。
