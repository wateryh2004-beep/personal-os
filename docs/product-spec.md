# Personal OS 产品与业务规范

状态：有效主规范。维护日期：2026-10-14。适用范围：私人 Personal OS 的目标、模块职责和业务不变量。早期 Phase 1 原文保存在 [历史规格](history/product-spec-phase-1.md)。

## 目标与当前范围

Personal OS 是余航的私人、长期可维护、可迁移的资料与决策系统。支持捕捉、行动、阅读、职业准备、个人记录和受控 AI 辅助；数据属于所有者，事实和来源可追溯。

当前代码包含 Today、Notes、Career、Inbox、Calendar、Tasks、Projects、Reviews、Files、Briefing、Investments、Leisure、Shopping、Travel、Settings 等工作区。这个清单说明现有模块范围，不表示每项均已通过当前生产验收；具体能力以相应契约、代码和带环境的证据为准。

保留单一私人 owner 使用，不新增公开注册、多用户协作、自动招聘爬取/投递/联系或自动交易。新业务通过明确任务和规格扩展；旧 Phase 1 对已经存在模块的排除不再代表当前范围。

## 产品取舍

优先完成用户真实任务，保持真实性、隐私与可恢复性。新入口先检查是否能通过已有模块、捕捉、搜索或详情完成。采用渐进展开组织复杂度，避免为每种内容新增一套维护系统。

首页舒展突出当前行动，专业工作区保持有序的信息量。视觉、交互与积极动效遵循 [设计规范](design-system.md)，不把功能数量作为体验改善的替代指标。

## 模块职责与不变量

| 模块 | 核心职责与必须保持的关系 |
| --- | --- |
| Today | 聚合重点、日程和继续事项；引用来源实体，写入回到各自领域，不建第二套任务表 |
| Inbox | 保留原始捕捉，处理或转换后保留来源关系 |
| Tasks / Calendar | Microsoft To Do / Outlook 为执行权威；提案、队列、缓存和已执行结果区分 |
| Projects / Areas | 以明确结果或持续责任组织工作，不复制任务执行权威 |
| Notes | 原始 Markdown 为正文权威；版本、并发冲突、原文和导出保持可恢复 |
| Files | 私有原件与元数据关联；封面、OCR、搜索和预览不能冒充原件或完整备份 |
| Experience Library | 手动收录外部经验正文、评论、图片和选区关联；原文追加、不自动抓取，图片原件复用私有 Files |
| Career | 目标岗位牵引准备；事实、表达、证据、能力、问题类型和面试形式分别建模 |
| Reviews / Memory / Decisions | 区分用户记录、确认事实、建议和历史判断；变更来源可追踪 |
| Briefing | 有限来源与条目、明确时间与出处；不形成无限新闻流或伪造消息 |
| Investments | 账本、持仓、策略、研究、回测与预测区分；可追溯口径，不执行真实交易 |
| Leisure / Shopping / Travel | 记录、规划与选择建议；不编造个人评分、购买或完成状态 |
| Settings / 状态层 | 提供连接、权限、预算、存储、导出与运行状态；展示实际配置和结果 |

领域细节见 [文档索引](README.md) 中的模块参考。

## 关键流程

1. 登录使用 owner 邮箱密码；无公开注册界面。登录成功后进入 `/today`。找回密码保留邮箱方式，答题方式由生产配置决定可用性，遵循 [安全规范](security.md)。
2. 全局捕捉创建原始输入，再按明确动作转换或关联任务、笔记等对象。
3. 查看/编辑从列表与搜索进入，返回保留必要的筛选、选中、滚动和未提交输入。
4. 外部任务、日程和应用内 AI 写入遵循既有确认/执行管道，只有真实完成才显示完成。
5. 归档、恢复、版本、导出与备份按 [数据规范](data-governance.md) 保持关系和原件范围。

## Career 核心规则

Facts 是可验证的底稿，Bullets 是面向方向的表达版本；两者不能覆盖。所有个人成果、时间、数量和职责必须有来源，AI 只能在事实范围内组织表达。

目标岗位、经历/事实/证据、问题类型、面试形式、Competency 与练习/Session 各自有明确职责。标准答案与思路拆解分开，阅读不等于掌握，历史答案和实践记录保持可追踪。

Career 复用 Notes、Tasks、Projects、Files、审计与导出，不另造平行底座。普通导出按安全规则脱敏，具体数据模型见 [Career 契约](career/DATA_MODEL.md)。

## 新功能的最低规格

写清触发问题、用户结果、范围、输入与权威源、正常/失败/取消流程、权限、副作用、验收和运行影响。使用 [功能模板](templates/feature-spec.md)；小修复可在 PR 内表达，避免机械增加文档。

验收必须覆盖完整用户动作及相关数据/安全边界。首屏、按钮、数据和动效的真实状态一致；演示数据不能被当作个人事实。未实现或未验证能力明确标注。

## 当前设计迁移

已确定暖白、深灰绿、轻卡片、宋体标题与无衬线正文，以及充分设计的空间动效。此处确认方向，现有实现的迁移见 [路线图](roadmap.md)；文档建设不代表全站视觉已变更。
