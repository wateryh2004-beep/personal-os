# 笔记连续操作 · 第一批 P1

状态：2026-10-25 实现规格；验收证据见 [验证记录](../verification/2026-10-25-notes-continuity-p1.md)。沿用 [设计](../design-system.md)、[动效](../design/motion.md)、[性能](../performance.md) 和 [资源所有权](../performance/navigation-resource-ownership.md) 规范。

1. 正文优先：路由仅开始当前文档与必要的附件元数据读取，以保留 primary PDF 的默认阅读方式。版本、笔记关联、文件夹管理与跨模块引用在打开详情后读取；AI 模型偏好在选择文字或打开 AI 后读取。版本列表只取最近 6 条元数据，用第 6 条判断“仅展示 5 个”，恢复操作仍按版本 ID 读取原有完整快照。读取失败显示真实错误，不用空结果伪装不存在。
2. 最近笔记：当前已验证 owner 的标签页内保留至多 6 篇文档，正文与标题采用约 3 MiB UTF-16 容量预算；超预算的活动文档仅在挂载时保留，离开后释放。后台读取去重，旧请求不能覆盖已确认保存；身份变化清空正文和位置，服务器 SSR 不读取标签页缓存。现有本机恢复草稿机制独立保留，不新增正文持久化。
3. 阅读与编辑：同一篇笔记保留 CodeMirror 实例和撤销历史；按 Markdown 源行映射阅读段落，返回时恢复选区/视口，阅读中移动后可继续对应段落。最近文档被重新挂载时恢复选区、滚动与阅读模式；内容变化时钳制旧位置。后台新版本只在编辑器干净时更新；有草稿时保留草稿和原修订号，显示版本冲突。
4. 长文输入：字数基于 CodeMirror rope 的变更范围增减，避免每键全文正则扫描。目录关闭时不解析，打开后在输入停止 160ms 后复用增量语法树，必要时才完成全文解析；目录跳转使用当前编辑器状态。自动保存、IME、上传占位符、真实失败提示和 CAS 冲突规则保留。

本批没有数据库迁移、依赖或生产配置变更。发布通过 PR 与既有检查，代码回退到上一生产部署即可；不删除或重写原件、快照和迁移。
