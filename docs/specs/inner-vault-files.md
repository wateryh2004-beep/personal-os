# 内层文件：独立口令与 ZIP 原件

状态：已实现；[验收记录](../verification/2026-11-14-inner-vault.md)。入口在 [外层暗格](private-vault.md) 的「文件 → 内层文件」。首次设置与外层不同的 12–256 字符口令；之后两层分别验证。内层退出即锁定，外层锁定时同时撤销内层会话。没有重置或跳过内层口令的入口。

## 使用与文件完整性

- 单个 ZIP 最多 2 GiB（2,147,483,648 字节），包括普通 ZIP 和用户自行加密的 ZIP。按原字节保存；不解压、预览、建立索引或发送给 AI。
- 先按 1 MiB 切片计算 SHA-256，再用两路、每片 8 MiB 的 Blob 直接 PUT 到已有的私有 Cloudflare R2。请求中不向 R2 发送应用 Cookie 或验证凭据。每次只签指定大小和编号的上传分片。
- 断网、锁定或主动暂停后重新选择同一 ZIP。名称、大小、SHA-256 一致才会续传；R2 已确认的分片不重传。最多 20 个活跃的未完成上传，续传有效期 6 天，仍受 R2 既有生命周期限制。已过期或损坏的记录可显式取消，完成的原件不会被取消或覆盖。
- 以 R2 的分片清单合并。合并后对象不能再经该 multipart ID 变更；服务端流式核对长度和完整 SHA-256，再在仍有效的两层会话下提交保存状态。合并答复中断可从已组装的对象重试校验。未知错误保留可恢复状态；已确认损坏不提供下载。
- 已完成的 ZIP 通过同站点流式下载，支持浏览器按字节续传，不向浏览器返回 R2 下载地址。点击下载需当前标签页通过两层验证；站内链接本身无下载权限，还需要绑定该文件、同一登录及两层会话、最长 5 分钟的 HttpOnly Cookie。每次打开链接或续传都重新检查会话；服务端确认任一层锁定后，旧链接立即拒绝新请求，再次解锁也不会恢复旧链接。传输中网站会每隔约两秒重新检查，发现锁定就停止供给后续字节；已发出的字节和本地副本无法收回。
- 服务端与外层分别限制 5 分钟闲置、最长 1 小时。可见的传输实际完成分片时计为活动；切后台遵循外层遮挡及锁定规则。被锁定时下一次进入需要重新校验上传。过期时不公开文件名、大小或原件。

## 数据与运行

`inner_vault_files` 是 ZIP 清单与可续传状态，不进入普通 `documents`、外层目录、搜索和任何系统或 Files 导出。原件只位于 owner UUID 后的独立 R2 路径，路径不含原始文件名；数据库约束禁止普通文件指针复用该路径。凭据校验值、尝试计数和会话也与外层分表。四张表和相关 RPC 都仅授予 `service_role`。下载 Cookie 只在验证当前标签页和两层会话之后签发，只能用于绑定的站内路径，不包含原始会话令牌。内层令牌只存当前标签页内存，数据库仅存散列，随外层会话删除级联失效。

内层是应用访问权限，不提供用内层口令派生密钥的端到端加密。原件由既有私有 R2 保管；如需文件级加密，可上传已经加密的 ZIP。备份时从内层单独下载 ZIP，保留受自己控制的副本；恢复到新环境时重新设置口令并上传副本。没有自动清理已组装但未提交的对象；这是为了避免将未知状态当作可删除文件。遗留对象或用户容量核算需在授权的存储维护中处理。

发布先审核并应用 `20261114103917_inner_vault_files.sql`，再部署代码。沿用现有服务端 Supabase、R2 和 CORS 配置，不创建公开桶或更改生命周期。先用获准的合成 ZIP 在对应验证环境测量大文件直传、断点续传、下载和约 2 GiB 的校验耗时，再用于真实文件。若需回退，保留所有表、RLS、命名空间约束和 R2 原件；用兼容版本恢复入口，不移回普通 Files 或删源。

平台行为参见 [Cloudflare R2 分片上传](https://developers.cloudflare.com/r2/objects/upload-objects/) 和 [私有签名 URL](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)。

下载改造只部署代码，无需迁移、配置或移动原件。切换时，旧版本已经签发的 R2 地址仍按原有效期到期（最多 60 秒）；等待这一窗口过去再判断旧地址是否失效。下载经过应用函数，慢速连接可能遇到单请求时限；两层仍解锁时可续传，旧链接到期或锁定后需回内层重新点击下载。
