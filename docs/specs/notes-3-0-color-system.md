# Notes 3.0 P1.1 — 文档色块、文字颜色与高亮设计规范

状态：**代码候选已实现**；是否合并、测试、发布及视觉验收以该批 PR 实际记录为准。
制定：2026-11-18。适用范围：Notes 编辑与阅读；本文件属于特定功能规格，不替代 [全站设计 v2](../design-system.md)。
前置计划：[Notes 3.0 执行路线图](notes-3-0-editor-upgrade.md)。

## 一、设计立场

不重做当前 CodeMirror / Markdown 编辑器。保留现有暖白 `#FFFEFA` 页面、灰绿 `#37594B` 主强调以及正文排版，用低饱和度配色给*有意义的完整段落*提供视觉层级，避免像多彩便签一样堆满页面。

提供三个相互独立的格式角色：

1. **整段色块（callout）**：带 3px 语义强调边、柔和背景和明确的类型标题，可容纳多段 Markdown（未来 P1.2）；不能把严重程度仅交给颜色表达。
2. **文字颜色（text/ink）**：只改变被选中片段的前景色，不增加块边框，也不隐含重要性。
3. **背景高亮（highlight/mark）**：只改变文字背后的色彩，保留适当的文字对比度和多行断行能力，不等于选区 hover 或搜索结果。

用户可以自主选择任何配色，下面的语义只是推荐用途。**语义 ID 稳定且是有限枚举**，不允许把正文中的任意 CSS 或 HTML style 注入页面。

## 二、五组颜色和四个角色

具体色值在唯一实施入口 [`src/app/notes-colors.css`](../../src/app/notes-colors.css)；可枚举 ID 与中文文案在 [`src/features/notes/editor/note-color-palette.ts`](../../src/features/notes/editor/note-color-palette.ts)。以下仅同步设计参数，不能分别复制成第二套运行时数据源。

| 语义 ID / 名称 | 推荐用途 | 浅色背景 | 浅色文字 | 强调边 | 行内高亮 |
| --- | --- | --- | --- | --- | --- |
| `info` 信息 / 雾蓝 | 参考资料、背景解释 | `#EDF3F8` | `#31556E` | `#587A92` | `#DCEAF6` |
| `warning` 提醒 / 杏橙 | 待办、注意事项 | `#FFF2E6` | `#865021` | `#AB713F` | `#FCE3C8` |
| `important` 重点 / 柔红 | 核心结论、特别强调 | `#FBEDEC` | `#883F3D` | `#B26864` | `#F6DAD7` |
| `idea` 思考 / 鼠尾草绿 | 观点、发现、灵感 | `#EDF3ED` | `#365A45` | `#668E6D` | `#DCECDD` |
| `quote` 引用 / 暖灰 | 引文、补充材料 | `#F4F1ED` | `#525A55` | `#838B83` | `#E8E3DC` |

字色与 highlight 在相同色系中保持一致，但两者独立控制。行内 mark 的文字使用 `--note-color-highlight-ink`，不是用浅色标记硬套同一色系的浅文字。

全部 5 组均预备深色数值；当前全站没有正式启用完整深色模式，因此仅在已有应用主题所有者显式加入 `:root.dark` 或 `:root[data-theme="dark"]` 时启用深色方案，不根据操作系统 `prefers-color-scheme` 私自切换 Notes 局部主题。

## 三、组件外观与节奏

- **色块边界**：单条 3px 左侧语义边 + 1px 外边框，右边圆角 12px、左边直角，内边距桌面 14px 18px、手机 12px 14px；背景纯色，无重阴影/复杂渐变，避免层层卡片。
- **排版**：沿用现有正文的 15–16px 与行高，不缩小内容；语义标题 13px 半粗，必须真实输出文字标题。内部多段、列表、引用、链接、表格、图片只需要保持原本 Markdown 结构。
- **段落间距**：色块上下 20px，手机 16px。长文本允许断行，不强制整块超出文档列宽。
- **状态**：如果色块内部存在可聚焦操作，`:focus-within` 使用全站 `--accent` 轮廓；hover 不添加不必要的位移或高饱和背景。阅读态与编辑态使用同一色值来源。
- **移动端和窄分栏**：色块不能因为长 URL/文件名而撑宽；保持至少两侧安全留白，编辑输入与颜色菜单将在 P1.3 遵守 44px 触摸目标。
- **可访问性**：色块正文、着色文字、mark 正文目标对比度 ≥4.5:1，强调边相对色块背景目标 ≥3:1；屏幕阅读器依赖文字标题，不依赖颜色；强制颜色模式下采用系统 `Canvas` / `CanvasText` / `Highlight` 与边框及文本提示。

## 四、工程接口

- 纯表现层选择器：`note-color-callout`、`note-color-text`、`note-color-highlight`。
- 稳定语义属性：`data-note-tone="info|warning|important|idea|quote"`，只用于映射有限 CSS Token。
- 活跃局部变量：`--note-tone-surface`、`--note-tone-ink`、`--note-tone-edge`、`--note-tone-mark`；单个色系的 4 个私有 Token 在相同 CSS 文件维护。
- 对非法颜色值，`parseNoteColorTone` 返回 `null`，不得用自由文本拼接 `style`、`className`、CSS 变量名或 `dangerouslySetInnerHTML`。
- 本阶段不修改用户正文、不新增数据库字段、不引入富文本 JSON 权威，也不将旧 Markdown 文本自动迁移或清洗。

## 五、P1.2 和 P1.3 的明确交接

**P1.2 存储与渲染**：优先验证 `> [!NOTE]` 一类兼容 GFM 的 admonition 语法，对 CodeMirror 可视编辑、react-markdown + remark-gfm + rehype-sanitize 的阅读及 HTML/PDF 导出建立完整一致的解析与安全契约；文字颜色与高亮没有标准 Markdown 编码，需另行比较有限内联语法和纯文本回退，不得在本阶段抢先冻结有损格式。折叠、Undo/Redo、选区、复制粘贴和现有文档可恢复性必须通过测试。

**P1.3 入口**：选区工具栏提供颜色/高亮/清除，斜杠菜单提供五种语义色块；外层工具栏只保留一个简洁入口，颜色选择须有可见名称、键盘焦点、取消/撤销、暗色及触屏状态。AI 结果不应默认插入色块。

## 六、验收与回退

P1.1 的必要验收为：5 组浅色及深色 CSS 值完整；边缘与文字对比度静态测试；运行时语义 ID 的非法输入拒绝；前端样式正确打包；不改变旧文档渲染与保存行为。

即使本批上线，旧文档与编辑器也不会直接出现颜色按钮或自动染色；这是 P1.2/P1.3 的后续交付。P1.1 回滚仅涉及 CSS、有限枚举及设计文档，无数据迁移或内容回写。
