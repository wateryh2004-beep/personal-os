# Notes 3.0 P2 — 逐段 AI 文档审阅、章节作用域及长文安全护栏

状态：代码实现候选；最终以本阶段 PR、CI 与真实界面行为验收为准。发布日期：2026-11-19。
基础：上一批 P2.1 双提供商、P2.2 原文快照、修订号及 CAS 保护；继续使用 CodeMirror + 原始 Markdown。

## 用户路径

1. Notes AI 面板在 Markdown 存在标题时显示“处理范围”：整篇或具体章节（兼容前言、H1–H6，跳过代码围栏中的伪标题）。未指定默认为整篇。
2. 对全文/章节执行润色、结构整理或翻译后，若变化规模适宜，生成 Markdown 行级修改区块：原文与 AI 建议并排展示，逐处“接受修改 / 保留原文 / 再次修改”，支持全部接受和全部保留。每个按钮只更新本地待确认草稿，不立即写数据库。
3. 所有改动决定完成后，在固定底部确认区一次性应用已接受内容，且沿用 P2.2 的原始版本快照、owner 认证、normal 隐私边界和修订号 CAS。另有「纯结果」阅读预览与复制。章节级应用仅替换原章节范围，不覆盖其他章节。
4. 对不适宜进行逐块 Diff 的极长文本，保留全文对照与用户控制，不假称已经有逐段原子应用。长文本推荐选择章节处理。

## 安全边界

- 保护旧的内部链接、双链、图片、围栏代码、行内代码，新增保护 GFM 表格、GFM 引用式五色色块、Notes 的 {{ink:tone|text}} / {{mark:tone|text}} 语义标记。模型可重排这些整体结构，但不能漏写、重复或修改其原始字节。
- AI 返回的结构占位符必须恰好出现一次；缺失/重复/虚构直接返回错误，不允许应用。用户逐段做混合选择后再执行一次全篇结构比对，不能因为“保留一段 + 接受另一段”出现重复/缺失结构。
- 输出撞到 token 上限则始终禁止写入，绝不把不完整内容当完整原文替换；不假装流式续写可以保证无重复和漏段。长文（至少 8000 字符）改写只保留不到 55% 体量也禁止整篇替换，需按章节处理。
- 不自动读取 sensitive/never 的笔记、不放开数据库读写权限、不保存用户原文到审计、不发布密钥；分段重新生成继续调用现有服务端 AI 行为与额度审计。
- 单篇笔记仍遵循现有 200000 字符的持久化上限；本批无需 SQL migration、不引入第二套编辑器或外部富文本存储。

## 工程边界与遗留

逐段审阅采用带有源偏移的行/段落修改区块，复杂重排有可能是一个大修改块，不能保证每一句形成独立卡片；超出 60000 字符的 Diff 总量或 80 个 hunk 时回退到原有结果对照。独立分段生成流水线与统一事实保真评测（P2.3/P2.7）、精确分模型计费（P2.6）仍是后续任务。

验收：Vitest 包括原文无损重建、接受/拒绝混选、结构保护与非法模型输出、章节代码围栏识别、长文/截断拒绝；TypeScript、build、Markdown 浏览器与移动端键盘回归，真实生产体验不得用合成 CI 测试冒充。
