# Startup and navigation investigation — 2026-10-05

Base: `a7436d3332b2fd12772b25b60ba2a25437eb3ccc`.

## Evidence and bounded changes

1. **Today had a serial database dependency.** The workspace RPC and candidate tasks started together, but `today_task_priorities` only started after the RPC supplied the profile timezone. Priorities now start concurrently using an owner-scoped UTC date ±1 day window, followed by exact profile-timezone date filtering. This covers UTC−12 through UTC+14, including date boundaries, without assuming the user's timezone. Missing selected tasks are still hydrated separately only when necessary. Errors, explicit-owner reuse and the existing reconciliation schedule are preserved.
2. **CPU idle was treated as network idle.** The shell could schedule other workspaces while the active workspace was still fetching. Idle warming now waits for the active resource to settle, subscribes before its first fetch, and cancels when navigation supersedes it. Serial background work also yields to an active resource refresh. Intent-based warming on hover/focus/touch remains available.
3. **The desktop Career link forced viewport prefetch.** That route's `getCareerHome` contains 11 database reads. The shell now uses controlled intent prefetch for this link too, instead of automatically starting a second dashboard while the first is loading. This is source-level evidence of a competing request path, not proof of how many requests a particular browser actually made.
4. **Initial usable-data timing was missing.** Previously `workspace-data-ready` required a navigation-click mark, so direct document entry silently skipped it. `initial-workspace-ready` now measures from the document navigation start to a data-backed component mount. In-app readiness remains a separate metric. `focus_wait` records the residual focus read wait after the workspace source resolves. Existing timing-only telemetry contains no record contents or identity.

Both perform three reads, one owner resolution, and one scheduling call for the unchanged reconciliation callback. This proves removal of one serial latency wave. **It does not mean production startup is 120 ms or has improved by 50%.** If missing selected tasks need hydration, that additional query is still required.
