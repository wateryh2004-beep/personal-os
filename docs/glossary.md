# 术语与信息结构

状态：有效规范。维护日期：2026-10-14。适用范围：界面命名、规格、数据契约和 Agent 沟通。

## 统一词义

| 术语 | 含义与边界 |
| --- | --- |
| 今日 / Today | 聚合下一步行动与日程的读模型；不是新的任务或日历权威库 |
| 收集箱 / Inbox | 保留尚未整理的原始输入；转换为实体时保留来源关系 |
| 领域 / Area | 持续承担的责任范围；不以一次完成为结束 |
| 项目 / Project | 有目标结果、可完成或归档的工作 |
| 任务 / Task | 可以执行与完成的行动；Microsoft To Do 是现有执行权威 |
| 日程 / Calendar event | 指定时间或全天安排；Outlook 是现有执行权威 |
| 笔记 / Note | 以原始 Markdown 为正文权威的可版本化记录 |
| 文件 / Document | 文件元数据与受保护的原件；预览、OCR 与摘要是派生物 |
| 经验资料 / Experience | 用户手动收录的外部一手经验笔记；capture 是追加式原文，图片通过媒体关联引用私有原件 |
| 履历事实 / Fact | 有证据、可核对的原始经历内容；AI 不得编造或静默覆盖 |
| 简历表达 / Bullet | 关联事实并面向岗位组织的表达版本 |
| 能力 / Competency | 题目或岗位需要考察的能力维度 |
| 问题类型 | 简历、行为、知识、压力等题目性质 |
| 面试形式 | 英文、群面、Panel、视频等表达或组织方式；与问题类型分开 |
| 证据 / Evidence | 支撑事实或答案的具体材料与来源关系 |
| 练习 / Practice | 围绕问题或目标进行的准备与作答活动 |
| 面试记录 / Session | 一次有上下文、题目和结果的实际或模拟面试 |
| 权威源 | 最终决定业务事实的系统或原件 |
| 缓存 / 读模型 | 为展示与性能派生的数据；失效不代表权威源为空 |
| 版本 / Revision | 用于快照或并发控制的明确版本；不得当作用户授权凭据 |
| 草稿 / 提案 | 尚未执行或确认的输入，不能标成已保存、已同步或已发送 |
| 归档 | 从默认工作视图移出；不等于永久删除原件 |
| 幂等 | 同一逻辑请求重试不会重复产生业务副作用 |
| 回退 | 恢复兼容的代码或配置；不等于逆向删除新数据 |
| RLS | 数据库按身份限制行访问的规则，独立于前端显示控制 |
| PR | 将一组修改提交审查、检查和合并的 GitHub 变更请求 |
| CI | 在代码提交后运行的自动检查；通过不等于已做真实生产验收 |

## 信息结构

主导航的代码权威为 `src/lib/navigation-registry.ts`，Career 局部导航由对应组件和领域规格定义。文档不得另造一份手工导航数组给代码长期使用。

新增入口先判断用户任务与实体归属，复用已有领域、搜索、捕捉和详情能力。界面名称面向用户，数据库技术名留在工程文档中。

同一动作和状态保持同一名称；产品中需要更名时同时检查导航、按钮、搜索、无障碍名称、规格与测试。历史数据 ID、外部 provider ID 和关联语义不能因改名而变化。

验证：同一概念无重复权威定义；用户能从入口名称预判操作；涉及时间时遵循 [日历时间契约](contracts/calendar-time.md)。
