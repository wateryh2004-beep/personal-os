# Files 浏览与照片管理（本地候选）

本轮复用 Files 的所有权、原件、文件夹和恢复包，不创建第二份照片库。`/photos` 转向 `/files?type=photo&view=grid`；现有文件不迁移、不重写。

## 操作

- 名称搜索同时匹配标题和原始文件名，支持当前文件夹＋类型的组合筛选
- 类型：照片、文档、表格、演示、音频、视频、压缩包、其他；依据 MIME 与扩展名分类，不修改文件事实
- 排序：上传时间最新/最早、名称、大小；日期明确为上传时间，不推断 EXIF 拍摄日期
- 列表/网格共用相同文件记录和重命名、移动、归档、下载、AI 可见性功能
- 每页最多100条，筛选或排序变更回到第一页；直接文件链接清除阻挡的筛选并定位到正确页
- 文件夹、名称、类型、排序、视图、页码记入当前页面 URL，支持刷新和 Back/Forward；没有新增持久化文件缓存
- 归档列表仍可查看全部文件夹，受名称/类型筛选，超过100条可继续显示；归档原件需先通过恢复校验，再下载，避免展示会404的旧下载按钮
- 恢复包始终覆盖全部 Files，而非当前筛选结果，界面明确提醒；保留既有单包/分包与校验流程

## 照片预览

网格请求同源 `/api/files/{id}/thumbnail`，从不把私人图片交给公共图片优化器或外部 AI。服务端继续验证 owner、对应bucket/path、available 和未归档状态。

支持 JPEG/PNG/WebP/AVIF/GIF，GIF只取首帧；应用 EXIF 方向并去除元数据。输入≤12MiB、≤2400万像素，输出≤640×640和512KiB WebP。原图、HEIC、SVG或超限文件仍保留并可主动下载，不伪造成功预览。源读取和转换有期限，失败显示占位。

前端只在网格/显式预览时请求缩略图，视口外不主动预取，并限制同一标签页最多3个进行中的缩略图请求；完成、错误、超时、卸载都会释放队列。响应为 private/no-store；不生成持久化缩略图，不增加R2对象或改变权限。

缩略图按需从原件读取，因此仍有读取/计算成本。本轮没有自动删除暂存副本、云端去重、自动整理、EXIF时间线、人脸识别或新增大文件上传上限。

## 验证

使用纯元数据、合成图片字节和mock provider；新增测试覆盖分类/排序/URL、过滤空状态、Back、链接定位、分页、解码格式/方向/资源界限和队列行为。

`scripts/files-browser-e2e.cjs` 在隔离的CI Files fixture里模拟JPEG缩略图，检查360/390/1440px的分类、排序、预览关闭、Back、搜索和空状态，确认没有原件下载或账号写入，并输出专属 `files-browser-evidence` 截图。

CI浏览器脚本只有在候选版本获准发布并运行后才能提供实际像素证据；本地单元测试不替代浏览器验收。所有生产文件、存储配置和访问权限均不改动。
