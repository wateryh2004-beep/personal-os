# 开发 Agent 工作规范

状态：有效规范。维护日期：2026-10-14。适用范围：修改本仓库的 Agent 与维护者。此文件不定义应用内 AI 的权限；应用内 AI 见 [AI 治理](ai-governance.md)。

## 开始任务

1. 读取根目录 [AGENTS.md](../AGENTS.md) 与 [文档索引](README.md)，检查目标目录中适用的其他指令。
2. 检查分支、工作树和当前目标提交；保留无关的用户修改。没有本地仓库时先通过已授权的 GitHub 连接取得可信基线，不把局部文档快照当完整运行仓库。
3. 读取任务对应的有效规范与相关源代码。使用索引的任务路由，避免把全部历史文档载入每个任务。
4. 从当前任务提取目标、范围、数据与权限边界、验收要求；已有信息足够则直接推进。

每个新实现任务重新核对相关规范；任务中规范更新、恢复压缩后的上下文或换分支时重新核对涉及部分。入口文件的自动加载取决于执行环境；通过 GitHub 连接在聊天中工作时也必须主动读取，不能假定所有工具都会自动加载。

## 授权与澄清

明确任务指示和已有授权优先于通用流程示例。范围内的实现、修复、测试和可逆文档维护自行完成；可独立完成的部分不因可选偏好未答而停止。

缺失信息影响结果时，优先调查已有证据，只问最关键问题。需要新的必要授权时，先准备具体可审查结果，并说明要执行的动作、对象和原因。不能重复索取已经给出的授权。

不得从“创建规范”“优化设计”推导出修改真实密码、永久删除资料、发送他人消息、开通付费资源或扩大数据共享的权限。自动审查拒绝某操作时，不改换通道绕过；采用实质更安全的方案，或说明拒绝原因和所缺授权。

## 调查与实现

优先 `rg` / `rg --files`。独立读取可以并行，依赖操作和修改依次进行。涉及产品或库当前行为时核对已安装版本的文档和必要的官方资料，不用记忆替代版本证据。

先找现有组件、领域逻辑、权限检查和适配层。遵循 [工程规范](engineering-standards.md)、[数据规范](data-governance.md) 与任务相关契约。不得引入占位业务数据、假成功、万能模型或平行权威源来让页面“看起来完成”。

界面任务先读 [设计规范](design-system.md)；包含状态切换和动画时再读 [动效规范](design/motion.md)。复用公共变量和组件，按目标规则逐步迁移，不把旧截图当永久审美约束。

任何鉴权、恢复凭据、审计、文件原件或外部写入变更，必须保留既有安全不变量。不得通过增大权限、关闭检查或降低验收标准来消除失败。

## 验证与交付

按 [质量规范](quality-standards.md) 选择与风险相称的检查。实际执行后记录结果，不把测试文件、截图脚本或部署链接的存在当作已通过。

交付说明包含：改了什么、为什么、实际验证、未验证或已知限制；涉及运行配置与数据库时说明发布顺序和回退。界面变化提供截图，动效提供录屏或可操作预览；证据只包含合成数据或已授权展示的数据。

真实生产密码、私人文档和外部收件人不作为默认测试对象。合成数据验证、真实测试服务验证、生产检查分别标注。

## 防止规范漂移

| 情况 | 应采取的动作 |
| --- | --- |
| 当前代码与目标规范不同 | 说明迁移差距；按本次范围修复，不宣称全站已迁移 |
| 两份有效文档冲突 | 查明确认记录与范围，更新冲突说明；受影响动作等待必要结论 |
| 发现历史检查失败 | 与固定基线对比，区分本次新增和存量；不删除或改写失败证据 |
| 新方向已明确获准 | 更新主规范与必要决策记录，无需反复确认同一方向 |
| 运行权限或环境不可用 | 完成独立检查，准确报告无法验证的范围，不伪造部署或测量结果 |

验证：PR 能追踪到使用的规范、目标提交与真实检查；不存在秘密、真实恢复答案或未授权数据外发。
