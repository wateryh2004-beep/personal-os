# 项目治理与规则维护

状态：有效规范。维护日期：2026-10-14。适用范围：Personal OS 的规划、开发、审查与维护。入口见 [文档索引](README.md)。

## 目标与取舍

Personal OS 服务于余航的私人资料、日常行动与决策。优先保持真实、可恢复、清晰、顺畅和可迁移，避免因为功能扩展制造第二套权威数据源或难以理解的维护工作。

发生取舍时按以下顺序判断：

1. 已授权范围、身份权限、数据真实性与完整性。
2. 核心任务能否完整完成，以及失败后能否恢复。
3. 日常使用的可理解性、响应速度、视觉与动效质量。
4. 实现和运行成本、维护复杂度。
5. 新增功能数量与展示效果。

性能与美感共同设计；不能通过公开私人缓存、伪造成功、丢弃数据或删掉必要标签达到视觉目标。

## 责任与授权

| 角色 | 责任 |
| --- | --- |
| 所有者余航 | 确定产品方向、体验偏好、业务事实、重要风险与对外权限；拥有仓库、账号和数据的最终控制权 |
| 开发 Agent / 维护者 | 核对事实与当前代码，提出并实现适当方案，执行验证，维护文档，明确未验证项 |
| 审查者 | 检查变更是否符合范围、数据与安全边界，核对测试证据与回退条件 |

任务中的明确指示及已有授权持续有效。常规实现选择、只读调查、范围内的可逆修改和验证由执行者推进；遇到真实缺失的必要授权才提出具体问题，并说明来源与影响。不得把文档中的工作流程变成每一步重新确认。

文档建设本身不授权发送消息、购买服务、创建付费资源、扩大数据发送范围、删除真实资料或修改真实账户密码。明确获准的操作按其授权范围执行。

## 文档权威与冲突处理

1. 平台及任务约束、所有者本次明确指示与持续有效的既有授权。
2. 本仓库有效的主规范和相关领域的安全、业务不变量。
3. 已采纳且明确限定范围的决策记录、功能规格或例外。
4. 历史记录、候选方案、模板和旧截图，仅提供背景与证据。

该排序是仓库内部维护规则，不改变执行工具本身的指令层级。更具体的文档可以细化规则；不能悄悄放松授权、隐私、审计或数据隔离。不同有效规则发生实质冲突时，先定位范围和证据，更新冲突条目；只暂停依赖这个冲突的操作，继续不受影响的工作。

现存代码说明当前行为，不自动证明行为正确。文档的目标规则也不证明代码已经实现。每次交付分别写明规则、实现与验证状态。

## 文档类型与状态

| 类型 | 内容 | 状态要求 |
| --- | --- | --- |
| 主规范 | 跨功能长期适用的要求 | 有效 / 已替代；指出适用范围 |
| 领域契约或操作手册 | 具体模块的不变量与操作步骤 | 区分已实现行为、目标和部署前提 |
| 功能规格 | 单次任务的输入、流程、异常和验收 | 草案 / 已采纳 / 实现中 / 已验证 / 已替代 |
| 决策记录 | 为什么选择方案及其后果 | 提议 / 已采纳 / 已替代；链接后续决定 |
| 验收或事故记录 | 某次环境中的观察与结果 | 标注时间、提交、环境和证据，不自动成为当前状态 |
| 模板 | 帮助新任务形成完整说明 | 未填写内容不产生授权、承诺或已完成声明 |

文档索引登记类型与权威范围。新增主规范只为明确的新职责；优先更新已有权威条目，其他文件通过链接引用。尚未登记的新方案按候选处理。

## 变更生命周期

任务开始：明确目标、范围、当前基线与验收；已有描述充分时直接使用，不强制为小修复新增规格文件。

实现期间：维护数据与权限不变量，采用能完整解决问题的最小边界；需求发生实质变化时更新规格和说明。

交付之前：按 [质量规范](quality-standards.md) 选择检查，记录实际结果；涉及运行行为时维护对应主规范、契约和手册。

发布与维护：按 [发布运行手册](release-operations.md) 执行；与已批准任务相关的发布授权持续有效。观察真实运行结果，必要时回退或做兼容修复。

## 决策、例外与文档更新

重要产品、架构、安全、设计方向或不可轻易撤销的选择写入 [决策目录](decisions/README.md)。常规代码重构、文字修正和合理的像素微调不需要单独决策记录。

例外必须记录适用对象、理由、风险、验证、维护者、复查触发条件及回归主规范的方法；使用 [例外模板](templates/exception-record.md)。例外不扩大任务授权。

主规范更新与对应实现尽量在同一变更中提交；如果先建立目标规范，应明确迁移未完成。不得为使现有代码看似合规而降低规则或把失败检查改成成功。

## 所有权、依赖许可与交接

仓库、域名、部署、数据库、对象存储和模型服务保持在所有者控制的账号中。交接仅记录资源用途、项目标识、访问方式、维护责任和恢复步骤，不记录密钥、密码、恢复答案或登录令牌。

依赖和素材保留必要的许可证、来源和归属信息。当前私有使用不代表任何素材允许公开或商业再分发；开源、公开展示或商业发布按 [条件性服务要求](future-service-requirements.md) 另行核对。

验证：变更的目标、规范入口、实现、证据和未完成项能从 PR 相互追踪；另一个维护者能按链接理解并继续工作。
