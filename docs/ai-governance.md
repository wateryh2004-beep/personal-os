# AI 数据边界与运行手册

状态：有效的应用内 AI 规范。维护日期：2026-10-24。它约束 Personal OS 内模型，不是开发 Agent 的工作许可；开发 Agent 见 [工作规范](agent-workflow.md)。当前工具能力以 [工具契约](contracts/agent-capabilities.md) 及实际 registry 为准，正文与检索关系见 [上下文契约](contracts/ai-context.md)。本文不扩大任何自动写入能力。

## 默认行为

- Context Planner 先使用当前页面与直接关联实体；一般对话不会自动扩展到历史 Notes。
- 扩大到近期笔记、回顾或检索结果必须由确定性路由触发，并在回答的“本次 AI 来源”中说明理由、模块、实体数和时间范围。
- 语义检索与长期记忆均为用户主动开启的选项；关闭时不参与上下文。此开关同时约束初始背景、专用记忆工具和跨域搜索的记忆分支；关闭后不通过工具补读。长期记忆可在 Memory 页面改为“永不发送给 AI”。
- Notes、Files、Memory 与 Decisions 均使用 `normal`、`sensitive`、`never` 三档。只有 `normal` 可进入模型工具或背景上下文；`sensitive` 和 `never` 一律在服务端过滤。来源面板可将实际用过的笔记或文件直接设为 `never`。

## 人工确认与审计

AI 只能生成建议或冻结提案。写入日程、任务、笔记、记忆及第三方同步仍须走既有确认队列；本次改动不新增任何自动写入权限。

每次调用写入 `ai_request_audits`：模型、界面用途、检索模式、脱敏来源摘要、上下文/输出上限、聚合 token、费用估算和最终状态。表中不保存提示词、模型输出、推理链、原文、Provider payload 或 API Key。普通用户通过 RLS 只能读取自己的审计记录；写入由 server-only service role 完成。

## 不可信内容与事实

外部文档、文件、网页和模型输出均作为不可信数据处理，不能通过内容中的指令改变权限、读取秘密或获得新工具。每次执行仍按确定性 schema、身份、对象归属、工具允许清单与已有确认边界验证。事实、推测和提案分别呈现，引用可追踪来源；缺失资料不能用虚构经历或状态补齐。

## 预算与降级

Settings → AI 边界可配置单次上下文/输出上限、每日和每月的调用与费用上限，以及每百万 token 的估算单价。Assistant、Today、Inbox 和 Briefing 的每次实际模型调用均在调用前完成统一预算检查与原子额度预留；超过上限会记录 `blocked_budget`，并清楚停止，而不是暗中扩大或替换模型。费用仅是可配置估算，不能替代供应商账单。单次检索字符预算由初始背景与整轮读工具共同使用；直接提交给 Notes 变换的正文继续遵循上下文契约，不因开启个人背景而截断。统计或审计不可用时停止模型调用，不将错误当成零用量。

## 运营与排障

先应用 `20260822031335_ai_governance_boundaries.sql`，再应用 `20260822032304_ai_usage_accounting.sql`，然后部署应用。若隐私字段不可用，Notes/Files 的 AI 检索会 fail closed（不发送该对象），而非回退到未过滤读取。审计记录按业务保留策略归档（`archived_at`）。预算统计包含未归档的已允许、已完成及可能产生费用的失败/取消调用；没有完整 usage 的失败/取消保留费用预留，不以零费用释放额度。该统计较原有“仅允许/完成”的口径收紧，防止失败调用绕过限额。需要排障时仅查看错误码、来源摘要和聚合用量，不得把请求正文写入日志。
