# AI 数据边界与运行手册

## 默认行为

- Context Planner 先使用当前页面与直接关联实体；一般对话不会自动扩展到历史 Notes。
- 扩大到近期笔记、回顾或检索结果必须由确定性路由触发，并在回答的“本次 AI 来源”中说明理由、模块、实体数和时间范围。
- 语义检索与长期记忆均为用户主动开启的选项；关闭时不参与上下文。长期记忆可在 Memory 页面改为“永不发送给 AI”。
- Notes、Files、Memory 与 Decisions 均使用 `normal`、`sensitive`、`never` 三档。只有 `normal` 可进入模型工具或背景上下文；`sensitive` 和 `never` 一律在服务端过滤。来源面板可将实际用过的笔记或文件直接设为 `never`。

## 人工确认与审计

AI 只能生成建议或冻结提案。写入日程、任务、笔记、记忆及第三方同步仍须走既有确认队列；本次改动不新增任何自动写入权限。

每次调用写入 `ai_request_audits`：模型、界面用途、检索模式、脱敏来源摘要、上下文/输出上限、聚合 token、费用估算和最终状态。表中不保存提示词、模型输出、推理链、原文、Provider payload 或 API Key。普通用户通过 RLS 只能读取自己的审计记录；写入由 server-only service role 完成。

## 预算与降级

Settings → AI 边界可配置单次上下文/输出上限、每日和每月的调用与费用上限，以及每百万 token 的估算单价。预算检查在模型调用前完成；超过上限会记录 `blocked_budget`，并清楚停止，而不是暗中扩大或替换模型。费用仅是可配置估算，不能替代供应商账单。

## 运营与排障

先应用 `20260822031335_ai_governance_boundaries.sql`，再应用 `20260822032304_ai_usage_accounting.sql`，然后部署应用。若隐私字段不可用，Notes/Files 的 AI 检索会 fail closed（不发送该对象），而非回退到未过滤读取。审计记录按业务保留策略归档（`archived_at`），预算统计只统计未归档的允许/完成调用。需要排障时仅查看错误码、来源摘要和聚合用量，不得把请求正文写入日志。
